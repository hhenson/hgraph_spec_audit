# Specification-only review: HGL eval delta pass-through

Date: 2026-09-30. Domain evidence: only files under `<spec-checkout>`. No implementation, external audit, measured trace, or reference execution was inspected or used to derive the expectations below. Paths in this report are relative to that specification root. Statements about what is implemented are document status labels, not verified implementation findings.

## Scope and conclusion (incorporating the latest operator clarification)

The required test boundary is HGL `test` → `eval(pass_through, ...)`, with replay and record operators wired and configured internally by eval. The graph inside eval must contain a replay source, an actual HGL runtime compute node owning a distinct output, and a recorder that copies output deltas. Replay and record may be normal HGL operators in the standard library with normal declared contracts; the eval caller does not directly invoke or configure them. HGL operator implementations/helpers are appropriate where the language permits them; minimal engine/buffer bridges may remain native.

The existing specification already makes eval inputs and results delta sequences. It does not yet give a complete typed delta representation or application operation for all temporal shapes. A generic `return delta(input)` solution would assume a result type the specification explicitly leaves open. Published-value deltas are also insufficient to reproduce all endpoint state: TS-5 expressly requires child-validity changes, and TSD additionally needs membership changes for keys with invalid children. Preserve this limitation visibly; do not invent a tombstone, null sentinel, or collection patch syntax.

A narrow dense scalar/atomic proof is already expressible. Structural and collection runtime behavior has substantial existing specification, but its harness language needs an extension. Reference and signal cases cannot honestly use the same literal-in/literal-out contract without further design.

## What is already specified

1. **Eval is a typed language form.** `language/docs/developer-guide/syntax-and-semantics.md`, “Tests and the evaluation harness” (lines 2102–2161), says the callee determines each sequence element's type; temporal arguments are per-cycle deltas, `_` is no tick, const arguments are constants, results are output delta sequences, and comparison is exact canonical delta equality. Dense index i means start + i engine steps. The result extends through the later of the last input cycle and last output tick. Mismatches report the first differing cycle/time. A harness sequence may be let-bound and compared inside a test, but cannot be passed as an ordinary function argument.
2. **Current documented first-pass scope is smaller.** `language/docs/user-guide/testing-and-running.md`, “Dense sequences,” “Timed sequences,” and “First-pass limits,” labels structural tuple harness elements and timed sequences provisional; scalar and atomic inputs are the documented implemented scope. Lists, sets, maps, rolling inputs, temporal structured deltas, and explicit optional-field clearing are reported unsupported. Do not confuse an agreed semantic shape with an implemented claim. There is a minor documentation mismatch: the developer guide allows an operator as eval's first argument, whereas the user guide requires a module fn/wrapper. An exact named fn avoids it.
3. **A compute node is distinct from composition wiring.** `language/docs/design/language-model.md`, “Function abstraction,” and developer guide “Runtime output” distinguish `=> value` composition from a body containing `when`, state, or injection. Runtime return writes its own output; no write means no output tick. Thus `fn pass_through(value: i64) -> i64 { when { return value } }` is a genuine scalar compute fixture. TS delta equals value, so this applies a scalar input delta without needing unspecified `delta(x)` lowering. A composition identity cannot substitute for it.
4. **Ownership and recording copies.** `runtime/time_series.md`, TS-21/TS-22, and `runtime/scalar_types.md`, VAL-1/VAL-16/VAL-17, require distinct owned output values and independent copies of anything retained beyond the cycle. A recorder must snapshot its delta, not retain a borrowed view later changed by the producer.
5. **Sparse struct updates are contextual.** Developer guide “Expressions” (lines 1588–1597) and “Runtime output” specify `delta<Quote>(bid: 1.0)`, named fields, no defaults, omission as no change, and null as an optional clear request. These are contextual update values, not ordinary parameter/result/state/collection-element/field types. They are admitted in a harness/replay sequence, an output context, or a contextually typed temporary. The clear form must remain rejected until its distinct native operation/encoding exists (lines 2024–2029).
6. **Known family behavior.** `runtime/time_series.md`, “Value and delta, by kind” and TS-1–TS-32, supplies recursive delta observations, invalidation, membership, netting, timestamp, reference, and window rules. These are specification contracts even though the chapter is marked draft; `runtime/conformance.md`, “Required and optional behaviour,” makes its rules required for claimed runtime conformance. Optional replay/record facilities must follow their written rules when provided; their optional status does not waive eval's language contract.
7. **HGL operator implementation ingredients exist.** Developer guide “Runtime output” exposes own-output collection mutation; “Collection traversal” provides modified/added/removed ranges; `language/docs/design/decisions/0015-pull-sources.md`, decisions 1–4, agrees source scheduling with alarm or yield/while. The ADR remains status-proposed with agreed spelling and differing backend status. A scalar replay operator can use a scheduler/source body, and a record operator can be an outputless runtime sink. This does not establish a general ordinary HGL parameter type for a harness sequence, a general delta buffer, or a recorder result-return bridge. Eval may lower its syntax into those operator configurations without permitting ordinary user functions to consume a harness-sequence value.
8. **Empty recording is meaningful.** `library/operator_contracts.md`, “Recording” / OP-11: a recording exists at recorder start; recording no ticks is empty, not absent; replay of it publishes nothing. Dense eval may still expose `_` cells to satisfy its time horizon, independent of that sparse buffer's emptiness.

Library scalars (narrow integers/floats, periods, ranges, frames, series) are native atomics or structs, per `runtime/scalar_types.md`, “Deferred”; they do not imply built-in syntax or blanket conformance. Cyclic buffers and queues are window implementation stores, not additional graph scalar families. Nil/unset/no tick/removal/empty reference are distinct semantic states, not additional payload families.

## Exact missing decisions and contracts

- **Typed delta values:** Specify a type-level delta shape for each temporal type, its equality, ownership/copy and contextual inference. Decide whether ordinary storable `delta<T>` is desired or whether eval maintains a compiler-owned representation at the eval boundary. Existing `delta<S>(...)` must not silently become a first-class type. No public delta type is necessary merely to make eval's input buffer typed.
- **Public test spellings:** Set add/remove, map upsert/remove, list sparse index/growth/truncation, recursive child patches, empty tick, and no tick need unambiguous constructors. Do not overload `{}`, `[]`, `_`, or `null` with several states without a rule. Struct delta omission/default rules already constrain the decision.
- **Domain of “apply delta”:** Choose payload-publication-only traces initially, or a full change record containing child invalidation, TSD membership, and structural length. TS-5 rules out claiming full reconstruction from payload-only deltas. Define order and preconditions for mixed structural operations, error/post-state and malformed indices/keys.
- **Transfer operation:** A generic runtime `delta(x)` needs a settled return representation and a corresponding legal own-output application path. Per-family HGL traversal/mutation can express parts today; a generic full sparse apply cannot be assumed. The smallest native bridge should expose an agreed operation, not embed all semantic behavior in C++ while calling the test “HGL pass-through.”
- **Empty-event preservation:** Set add/remove cancellation is still a tick. A copied empty set delta must publish once even if no mutation loop body executes. Decide explicitly how output initialization, empty dictionaries/fixed collections, and empty patches tick; do not infer this from scalar return behavior.
- **Capture boundary:** A record operator needs a typed owned append/capture channel scoped to one eval, initialization at start, extraction after run, lifetime/error cleanup, with eval responsible for its construction/configuration. Operator visibility is not prohibited. Specify whether it captures payload deltas only or a richer event stream. A scalar `state` list or native holder cannot be presumed from the current open non-scalar state/capture rules.
- **Invalidation admission:** Default when requires valid input. An input becoming wholly invalid does not tick. A full-state forwarding fixture must define how it receives and forwards invalidation independently of valid modified payloads. Merely iterating modified-valid children will miss it.
- **Time and boundaries:** Dense step/origin alignment, finite all-silent horizon, empty input sequences, different sequence lengths, source end, timed duplicate/reordered keys, and delayed trailing output must be explicit. Existing source ADR says eval needs an input bound; explicit end remains open. Preserve the existing dense horizon and avoid accidentally treating replay exhaustion as node/graph termination.
- **Refs/signals:** Use separately designed fixtures and permitted HGL signatures. Literal reference identities cannot be invented, and signal outputs cannot be admitted without changing the language.
- **Status hygiene:** Update user guide provisional/first-pass labels alongside newly agreed contracts. Avoid treating archival implementation descriptions or external links as accepted semantics.

## Reasoned minimal traces, fixed before observation

These are semantic notation, not proposed HGL collection syntax. `—` means no tick; `{field:delta}` means sparse delta; `+`/`−` describe membership. Each case starts invalid unless specified. Replay and pass-through have distinct outputs. Tests must compare output deltas, never reconstruct expected data from observations.

|---|---|---|
| Scalar S1 | 7, —, 7, 9 | 7, —, 7, 9. TS delta=value; idle retains value with nil delta (TS-2); each admitted runtime return ticks, including equal repeat. Run once for each admissible scalar type using two well-typed values. |
| Atomic A1 | atomic tuple (1,2), —, (1,3) | Whole (1,2), —, (1,3). Atomic boundary never becomes field patch. Apply same pattern to complete scalar struct/list/set/map payloads with equality. |
| All-silent E1 | —, —, — for scalar input | —, —, — dense result; recorder starts but has no records (OP-11), default compute never evaluates on valid modified input. |
| Named bundle B1 | {bid:1}, —, {ask:2}, {bid:1} | Identical sparse sequence. Final held value is {bid:1,ask:2}; first held value includes ask:nil. Returning whole current input at c2 would wrongly tick bid too (TS-24). |

| Signal Q1 | Concrete source ticks payloads 4, —, 4; signal consumer returns true per activation | Marker trace true, —, true. This tests input tick erasure without an illegal signal output. It is a different fixture class from same-type pass-through. |

Two deliberately non-reconstructible counterexamples must precede implementation:

- Start TSB value {a:1,b:2}; invalidate b. Valid-modified payload delta contains no b value, while value becomes {a:1,b:nil}. A payload-only recorder can compare the sparse publication but cannot prove invalidation was forwarded. Need a validity event or explicitly exclude this domain (TS-5/7/24).
- Add TSD key k without publishing its child. Value contains k:nil and added(k) is true, but published-child delta need not contain k. Value-delta replay alone cannot recreate the membership; missing information cannot be repaired by choosing a sentinel after observing a backend (TS-5/19).

The traces are prospective derivations. Cases that depend on a missing harness/apply contract must be recorded as specification proposals, not passing runtime conformance. `runtime/conformance.md`, “Accepting an expectation,” requires expectations before execution and preservation of disagreements and rulings; no actual output should overwrite these expectations.

## Isolated specification-extension PR boundaries

1. **Eval typed delta sequences and operator composition.** Define family-specific harness constructors/equality/copy; retain existing contextual struct constructor; declare that eval wires replay and record operators internally and its caller supplies only eval arguments; pin dense/sparse alignment, silence/empty-event distinction and status labels. Include only language contract and reasoned examples. Replay/record operator declarations may be public standard-library contracts.
2. **Runtime delta application and full-change boundary.** Specify pure publication-delta apply separately from invalidation/membership/length effects, nested application order, owned output effects and empty-event publication. Decide whether the first deliverable deliberately excludes full-state transitions. Include spec-only pre/post-state traces and failure rules. Do not tie representation to implementation internals.
3. **HGL replay/record operator contracts and source/capture capabilities needed by eval.** Define only missing typed buffer/source/sink bridges and lifecycle/ownership/extraction contracts after PRs 1/2 settle. Reuse alarm/yield/while/traversal/mutations; keep scheduling and accumulation behavior authored in HGL where expressible. Define ordinary replay/record operators as needed, with eval owning their wiring/configuration in these tests.
4. **Reference and signal conformance fixtures.** Define scoped reference identities, empty designation, target ownership and expiry comparisons; retain signal's input-only restriction and use an appropriate observation fixture. This can be deferred without mislabeling scalar/collection coverage as “all families.”

Implementation PRs in each compiler/runtime and any portable HGL support can then cite one settled specification revision, with the independent pre-observation traces retained. No implementation file or tracked repository file was changed for this review.
