# Scalar pass_through acceptance-test reasoning

Semantic evidence is exclusively the hgraph_spec checkout at
`<spec-checkout>`.
No Python/C++ hgraph implementation, hgraph_spec_audit, Rust/compiler
implementation, or reference execution was consulted.

## Contract evidence

- `language/docs/developer-guide/syntax-and-semantics.md`, “Tests and the
  evaluation harness”: temporal harness-sequence elements are per-cycle
  input deltas; `_` is no input tick. Dense output spans the later of the
  final input cycle and output tick, filling silent cycles with `_`, and
  comparison requires equal lengths and element-wise exact equality.
- `language/docs/user-guide/testing-and-running.md`, “Assertions and
  evaluation” and “Dense sequences”: `eval` wires replay and recording
  internally. A typed `fn` wrapper supplies the exact callee signature when
  testing an operator. Tests must not configure or invoke replay/record.
- `language/docs/developer-guide/syntax-and-semantics.md`, handler selectors:
  bare `when` selects modified temporal inputs and requires their validity.
- `runtime/time_series.md`, TS-1/TS-2/TS-3 and publication rules: scalar
  publication is a tick even when equal to the retained value. Value is
  retained while idle; delta is absent when unmodified.
- `runtime/cases_atomic.md`, ATOMIC-RETENTION: publishing 7, idling, then
  publishing 7 again produces a second tick with delta 7. ATOMIC-ZERO shows
  a first publication of zero is valid and modified, not absent.
- `library/operator_contracts.md`, OP-1/OP-4: forwarding publishes every
  admitted tick, including equal values; an invalid input does not produce
  a substitute default value.
- `library/operator_contracts.md`, OP-11: recording starts even if the
  time series never ticks; the resulting recording is empty, not absent,
  and replaying it publishes nothing.
- `runtime/node.md`, NOD-5 and “Eval”: a compute writes its own output;
  writing nothing means no output tick.

## Target integration inspection

The allowed HGL target package declares `pass_through<T>(ts: T) -> T` in
`hgl/hgraph/control.hgl`. Its implementation in
`hgl/hgraph/impl/control.hgl` is:

```hgl
impl fn pass_through<T>(ts: T) -> T { when { return ts } }
```

The `when` body is runtime computation with its own output. It is not a
composition-only `=> ts` identity. For these scalar TS types, the admitted
input tick's delta is the whole scalar value, so returning `ts` applies that
scalar delta to the compute's output. The target explicitly instantiates
bool, i64, f64, str, date, time, datetime, and duration. The new test wrappers
only wire this existing operator; they do not shadow or replace its body.

## Expected traces, derived before authoring tests

Each type uses the following distinct values A and B:

| Type | A | B |
|---|---|---|
| bool | false | true |
| i64 | 0 | -7 |
| f64 | 0.0 | 1.5 |
| str | "" | "delta" |
| date | @1970-01-01 | @2024-02-29 |
| time | @00:00 | @12:34:56 |
| datetime | @1970-01-01T00:00Z | @2024-02-29T12:34:56Z |
| duration | 0us | 1s |

Four cases apply independently to every type:

1. First/equal/distinct ticks: input `[A, A, B, A]` must produce
   `[A, A, B, A]`. First A initializes the output; the next A is an equal
   publication and still ticks; B changes the value; final A verifies
   subsequent forwarding. False, numeric zero, and empty string are values.
2. Leading/interior/trailing silence: input
   `[_, _, A, _, A, B, _, _, A, _, _]` must produce exactly the same trace.
   The first two cycles have no admitted input. Cycle 2 initializes A;
   cycle 3 retains A but emits no delta; cycle 4 publishes equal A again;
   cycle 5 publishes B; cycles 6/7 are silent; cycle 8 publishes A; cycles
   9/10 remain present as silent positions in the dense output. (Indices
   are zero-based.) The output cannot pad silence with its retained value,
   trim trailing positions, suppress equal input ticks, or emit startup
   defaults.
3. All silence: input `[_, _, _, _]` produces `[_, _, _, _]`. There are
   four input positions and no admitted publication or output ticks.
4. Empty input: input `[]` produces `[]`. There are no input positions,
   no admitted publications and no output ticks, so no dense position is
   justified. The recording still exists as an empty recording (OP-11).

This is 8 typed wrappers, 32 named tests, and 32 eval assertions. Expected
traces are explicit HGL sequence literals, never generated by executing an
implementation.

## Collection boundary and specification gaps

The specification describes collection runtime values/deltas, but does not
provide a complete implemented HGL eval encoding for structural collections.
`testing-and-running.md` labels structural tuple elements provisional and
lists structural tuple/list/set/map/rolling eval inputs as unsupported in
the current first pass. No supported syntax is specified there for set
membership removal, dictionary key withdrawal, nested structural deltas,
or representing an explicit valid-empty structural publication separately
from a silent harness cycle. Those require a specified harness schema and
collection pass_through/output-application contract before acceptance
tests can claim them. Atomic collection scalar snapshots would test a
different contract and are not substitutes. This suite makes no claims
about collection support, invalidation, reference routing, scheduled
ticks, timed sequences, NaN equality, or graph node identity inspection.

Execution on the target compiler is a later validation step. No reference
implementation is to be executed to derive expected outputs.
